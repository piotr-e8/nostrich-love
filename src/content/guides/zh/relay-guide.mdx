## 中继如何工作（3 分钟）

<RelayVisualizer client:idle />

<Callout variant="info">
  **基于之前的知识：** 本部分简要回顾 [中继详解](/zh/guides/relays-demystified) 中的邮局类比。如果你记得中继如何工作，请跳到 [中继类型](#中继类型2-分钟)。
</Callout>

### 简单解释

**中继是存储并分发你的 Nostr 消息的服务器。**

把它们想象成邮政信箱：

- 你把信件（你的帖子）的副本投到好几家邮局
- 每家邮局保存自己的那份副本，彼此之间不会转发
- 收件人从你们双方都使用的某家邮局取件

在 Nostr 中：

- **你**写一条笔记（帖子）
- **客户端**向你连接的每个中继各发送一份副本
- **中继**存储它并提供给任何来请求的人，但默认不会把它传给其他中继
- **关注者**从你发布到的那些中继上取到它。你的客户端会把这份中继清单公开发布出去（这就是 NIP-65），别人的应用因此知道该去哪里找你。至于那些忽略这份清单的老应用，只有当你们恰好共用同一个中继时，它们才能看到你的帖子

### 为什么这很重要

你的帖子同时存放在好几个中继上，所以其中一个宕机并不会让你从网络上消失，也没有谁能一次性把你写的东西从所有中继上抹掉。如果某个中继开始拒收你的作品，你换一个就是了，读者会跟过来。正因为这种开放性，中继彼此之间差别很大：有免费的，有收费的，有过滤严格的，也有几乎什么都放行的，你自己挑一个能接受的组合。

### 技术概览 [高级]

在底层，中继使用 WebSocket 连接：

```
Client ←→ WebSocket ←→ Relay Server ←→ Database
```

当你发帖时：

1. 客户端用你的私钥对消息签名
2. 客户端通过 WebSocket 发送到已连接的中继
3. 中继验证签名
4. 中继将其存入数据库
5. 中继向订阅者广播

<Callout variant="info">
  你不需要理解这些技术细节。只需知道：正是中继让 Nostr 在没有中心化控制的情况下运转。
</Callout>

## 中继类型（2 分钟）

### 免费公共中继

这类中继由志愿者和社区成员运行，任何人都可以往上面发帖。它们不收费，大多数人是从这里起步的，网络上相当一部分流量也由几个大型免费中继承担。代价是：一个免费中继的稳定程度，取决于维持它运转的那份善意，偶尔卡顿或者宕机是正常的。

**示例：**

- `wss://relay.damus.io`（最流行）
- `wss://nos.lol`
- `wss://relay.snort.social`
- `wss://nostr.mom`

<Callout variant="warning">
  **避开 relay.nostr.band：** 这个中继已长时间离线或不稳定。许多指南仍在推荐它，但你应该改用上面列出的替代选项。
</Callout>

### 付费中继

往这类中继写入需要付费，通常是通过闪电网络支付一笔比特币。这笔钱换来的是一位有理由把机器维护好的运营者：速度快、垃圾信息少、出问题时有人回应。日常发帖并不需要这些，而且有些付费中继会限制你的存储量，所以把它当成一次升级，等免费中继不够用了再考虑。

**示例：**

- `wss://nostr.wine`（一次性入场费）
- 各种私人中继

### 专门中继

有些中继只服务于一个主题、一个地区或者一个应用。房间小，意味着里面的人更可能真的在乎你做的东西，而且在通用中继之外多加一个也不花你什么。只是别只靠一个小众中继，因为在那里只有知道它的人才看得见你。

**示例：**

- 专注比特币的中继
- 区域性中继（欧洲、亚洲等）
- 特定语言的中继

<Callout variant="success">
  **从免费公共中继开始。** 之后如果需要更好的性能或想支持网络，再添加付费中继。
</Callout>

## 选择中继（5 分钟）

### 推荐的入门组合

连接以下这四个免费中继即可获得良好覆盖：

```
wss://relay.damus.io          (主力 - 最流行)
wss://nos.lol                 (快速、稳定)
wss://relay.snort.social      (Snort 客户端背后的中继)
wss://nostr.mom               (规模较小、社区运营)
```

如果你之后想在组合里加一个付费中继，`wss://nostr.wine` 是最广为人知的选择，本文后面会讲到它。

<Callout variant="info">
  **关于去中心化的说明：** 上面这些热门中继非常适合入门，但只依赖少数几个大型中继会导致权力集中，违背 Nostr 的去中心化精神。当你逐渐熟悉之后，可以考虑添加一些小型的社区运营中继和付费中继，以支持网络多样性。目标是大小中继的健康组合，别把鸡蛋都放在一个篮子里。
</Callout>

### 读取中继与写入中继

中继设置通常分成两栏。写入中继存放你自己的帖子，新关注者的应用就是去那里找你的。读取中继则是你用来接收回复和提及的那些。当你保存中继设置时，客户端会把这份清单作为一条公开笔记发布出去，任何别的应用都能读到，别人因此不用你多说一句就能找到你的帖子，没有什么需要你手动分发。想了解其中的机制，可以看[发件箱模型指南](/zh/guides/outbox-model)。

### 选择标准

**1. 正常运行时间。** 一个有一半时间是宕机的中继，你的读者根本连不上。想在添加之前先查一查，nostr.watch 上有运行时间记录。

**2. 地理位置。** 物理距离近的中继用起来更快，所以留一两个在附近，再配几个远一点的来扩大覆盖。

**3. 内容政策。** 有些中继对垃圾信息过滤得很凶，有些则几乎照单全收。读一读运营者公开的政策，挑一个你能接受的。

**4. 速度。** 如果每次打开应用，某个中继都要花好几秒才连上，那它带来的麻烦已经超过好处了。

**5. 运营者。** 一个愿意回答问题、把中继的规则公开说清楚的人，比任何硬件参数都值钱。

### 在哪里找中继

- **nostr.watch** - 中继正常运行时间监控
- **nostr.info** - 中继目录
- **客户端推荐** - 许多客户端会推荐默认中继
- **社区列表** - 在 Nostr 帖子中分享

### 需要多少个中继？

| 用户类型   | 推荐数量 | 上限 |
| ---------- | -------- | ---- |
| 初学者     | 3-5      | 10   |
| 活跃用户   | 5-10     | 20   |
| 重度用户   | 10-15    | 30   |
| 机器人/服务 | 20+      | 50+  |

**并不是越多越好：**

- 更多中继 = 更多带宽消耗
- 超过 10-15 个后收益递减
- 重质不重量

<Callout variant="warning">
  不要随便添加 50+ 个中继。那会浪费带宽并拖慢你的客户端。坚持使用 5-10 个高质量中继。
</Callout>

## 添加中继（3 分钟）

### 通用步骤（大多数客户端）

1. **打开设置**
   - 通常是齿轮图标或"设置"菜单

2. **找到中继部分**
   - 寻找"Relays"或"Network"（中继/网络）

3. **添加新中继**
   - 点击"+"或"添加中继"
   - 输入 WebSocket URL：`wss://relay.example.com`
   - 保存

4. **验证连接**
   - 应显示绿点或"已连接"
   - 可能需要几秒钟

### 各个应用里，这项设置在哪

应用每次更新都可能挪动菜单位置，所以下面只是给你一个大致方向。在 **Damus** 和 **Amethyst** 里，打开设置，找"Relays"。在 **Primal** 里，它在设置下面的 Network 中。**Iris**、**Coracle** 这类网页客户端，则藏在头像后面的设置菜单里。如果你看到的界面和这些都对不上，就在应用自带的设置搜索框里输入"relay"。

想在不动真实账号的前提下把整个点击流程练一遍，可以用 [sandstr.app](https://sandstr.app) 上的客户端模拟器。

### 连接问题排查

**"连接失败"**

- 确认地址是以 `wss://` 开头，而不是 `https://`、`http://` 或 `ws://`
- 中继可能宕机了
- 几分钟后重试

**"超时"**

- 中继太慢或过载
- 换一个中继试试
- 检查你的网络连接

**没有帖子加载出来**

- 可能需要等待同步
- 尝试刷新
- 检查该中继是否有你关注者的帖子

## 付费中继（3 分钟）

### 为什么付费？

付费中继背后有一位负担得起认真对待它的运营者。这通常体现为：宕机更少，回复里的垃圾信息更少，你报告问题时真的有人回应。什么时候该考虑？当免费中继开始让你失望的时候，或者当你的作品档案对你重要到值得放在一个有账单的地方的时候。

### 流行的付费选项

**nostr.wine** 收取一次性的入场费，用闪电网络的比特币支付（写下这段时大约是 19,000 sats，当前价格请以网站为准）。你换到的是一个速度快、维护得当的通用中继。

**私人中继**是为某个群体运行的：一家杂志、一个社区、一个家庭。价格不等，通常靠邀请加入。如果你本来就属于某个有自己中继的圈子，值得去问一问。

### 设置付费中继

1. **选择服务商**
2. **付款**（通常是比特币/闪电网络）
3. **接收凭证**（如果需要）
4. **添加到客户端**（与免费中继相同）
5. **享受更好的性能**

<Callout variant="success">
  **混合方案：** 使用 3-5 个免费中继 + 1-2 个付费中继。两全其美。
</Callout>

## 你自己的中继 [高级]（2 分钟）

自己跑一个中继，意味着你的作品有一份副本存在一台别人管不着的机器上，规则由你定。它同时也意味着要租一台服务器（每月大约 5 到 20 美元），把域名指过去，并且愿意在终端里干活。绝大多数创作者一辈子都用不上这个，跳过它也不会有任何损失：把作品发布到别人运行的中继上，本来就是使用 Nostr 的常规方式。

如果你还是想试试，有三个中继程序反复被提到。**strfry** 用 C++ 写成，是快而精简的那一个。**nostr-rs-relay** 是 Rust 版本，在积极开发中。**nostream** 用 TypeScript，三者里安装最省事。每个项目都在自己的仓库里维护安装说明，那些说明的时效性是本指南给不了的，所以从仓库出发，别照抄现成的命令清单。

<Callout variant="warning">
  中继是一件需要持续跑下去的事，不是装好就完的事。磁盘会满，软件要更新，备份得检查。除非你想接下这份活，否则别开始。
</Callout>

## 故障排除（3 分钟）

### 常见问题

**信息流是空的**

- 连接的中继不够多
- 中继宕机了
- 关注的人不够多

**解决：**

1. 检查中继连接
2. 添加更多热门中继
3. 关注更多人

**帖子没有显示出来**

- 中继拒绝了帖子（频率限制、内容政策）
- 客户端没有广播
- 网络问题

**解决：**

1. 检查中继政策
2. 换一个中继试试
3. 重启客户端

**性能缓慢**

- 中继太多
- 列表里有慢速中继
- 网络连接不佳

**解决：**

1. 移除慢速中继
2. 坚持使用 5-10 个高质量中继
3. 检查网络连接

**无法连接到中继**

- 中继宕机了
- URL 写错了
- 防火墙拦截

**解决：**

1. 在 nostr.watch 上检查中继状态
2. 验证 URL 格式（wss://）
3. 换一个网络试试

### 监控工具

- **nostr.watch** - 中继正常运行时间和统计数据
- **nostr.info** - 中继目录和信息
- **客户端中继状态** - 大多数客户端会显示连接状态

### 何时切换中继

**在以下情况切换：**

- 经常离线
- 非常慢
- 审查你在意的内容
- 有更好的替代选择

**不要仅因为以下原因就切换：**

- 漏掉了一条帖子
- 暂时变慢
- 小小的不便
