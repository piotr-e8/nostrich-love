## 为什么使用多个客户端？（2 分钟）

### 选择的力量

Nostr 的超能力是你的身份到处都有效。聪明的用户通过将多个客户端用于不同目的来利用这一点。

### 常见用例

**移动 + 桌面：**

- **手机（Damus/Amethyst）：** 快速检查、随时随地发帖、通知
- **桌面（Iris/Snort）：** 稍长的帖子和讨论串、重度浏览、工作时间

写完整的文章是另一回事。Iris 和 Snort 是为短帖设计的，所以如果你写的是长文，请换一个专为长文发布做的客户端。[YakiHonne](https://yakihonne.com) 是常见的选择，浏览器里能用，iOS 和 Android 上也有。

**两个独立身份：**

- 有些人会再生成一对密钥用作个人账号，然后给每对密钥各配一个客户端
- 分开来自这两套密钥，而不是来自应用。同一对密钥装在两个客户端里，仍然只是一个公开身份：npub 一样，公开的帖子到处也一样

**不同功能：**

一个客户端可以靠把某件事做好来赢得自己的位置：Amethyst 强在中继和媒体控制，0xchat 强在私信，Coracle 适合逐个浏览中继。除此之外，你的账号在它们里面的表现都是一样的。

**备份与冗余：**

- 如果一个客户端坏了，你有替代方案
- 安全地测试新功能
- 比较界面

### 好处

好处在于，你不必再为了迁就一个应用而改自己的习惯。在写着舒服的地方写，在读着舒服的地方读，两种情境是你有意分开的，而不是碰巧分开的。换客户端的代价很小，因为你的身份、帖子和关注都存在中继上，不在任何一个客户端里。

<Callout variant="info">
  **你不需要多个客户端。** 但如果你认真对待 Nostr，它会解锁新的工作流。
</Callout>

## 同步策略（3 分钟）

### 什么自动同步

**通用（跨所有客户端工作）：**

- ✓ 你的身份（npub）
- ✓ 你发布的帖子
- ✓ 关注列表
- ✓ 个人资料信息
- ✓ 反应（点赞、转发）

私信是例外。私信只有在第二个客户端支持同一套私信标准（现行的是 NIP-17）、并且连上了你的私信中继时，才会在那里出现。还停留在旧标准上的客户端，会给你看另一份互不相干的对话记录。哪些客户端在哪一边，见[私信](/zh/guides/nip17-private-messages)。

### 什么不同步

**客户端特定：**

- ✗ 应用设置（主题、字体）
- ✗ 通知偏好
- ✗ 应用本地的屏蔽和只在这个应用里生效的隐藏（标准的静音列表是会同步的）
- ✗ 草稿帖子
- ✗ 本地书签
- ✗ 自定义动态/算法
- ✗ 应用特定数据

### 同步过程

**工作原理：**

1. 你从客户端 A 发帖
2. 客户端 A 发送到中继
3. 客户端 B 连接到相同的中继
4. 客户端 B 看到你的帖子
5. 你的帖子和关注保持同步

关键全在第三步。两个客户端都会到你已发布的中继列表里去找你的帖子，所以如果其中一个被指向了一批你从没发过帖的中继，它给你看到的就是一个缩水版的自己。请在你用的每个客户端里保持同一份中继列表。客户端怎么找到这份列表，[发件箱模型](/zh/guides/outbox-model)里有解释。

**时间延迟：**

- 通常瞬间到几秒钟
- 取决于中继速度
- 客户端刷新率不同

### 非同步数据的解决方法

**设置：**

- 手动配置每个客户端
- 记录你的偏好
- 使用类似的设置以保持一致性

**静音/屏蔽：**

- 你的静音列表属于协议的一部分（NIP-51），所以它跟着账号走：在一个客户端里静音某人，其他客户端会跟上
- 留在原地的是应用本地的东西，比如某个应用自己的"隐藏这条"开关，或者客户端自带的过滤设置
- 不需要导出或导入

**草稿：**

- 使用外部笔记应用
- 在客户端之间复制粘贴
- 或立即发布

**书签：**

- 使用 NIP-51 列表（如果支持）
- 外部书签工具
- 基于 Nostr 的书签服务

<Callout variant="success">
  **专业提示：** 专注于同步的内容（帖子、关注），不要太担心不同步的（设置）。
</Callout>

## 桌面 + 移动（3 分钟）

### 推荐配对

**iOS 用户：**

- **移动：** Damus（干净、快速）
- **桌面：** Iris（网页版）或 Snort（网页版）
- **为什么：** Damus 针对 iOS 做了优化，网页客户端则随处可用

**Android 用户：**

- **移动：** Amethyst（功能丰富）
- **桌面：** Iris（网页版）或 Coracle（网页版）
- **为什么：** Amethyst 是 Android 的最佳选择，与快速网页客户端配对

**跨平台：**

- **移动：** Primal（iOS + Android）
- **桌面：** 相同的 Primal 账户（网页版）
- **为什么：** 跨设备统一体验

### 工作流示例

**内容创作者：**

- **在桌面起草**（Iris）- 写作、编辑、格式化
- **从桌面发布** - 点击发布
- **在移动版检查互动**（Damus）- 回复、闪电打赏
- **在移动版快速回复** - 在外出时

**社区经理：**

- **在移动版监控**（Amethyst）- 通知、提醒
- **在桌面深度互动**（Snort）- 长回复、线程
- **在移动版私信** - 快速对话
- **在桌面计划活动** - 详细帖子

**休闲用户：**

- **在移动版浏览**（任意）- 在休息时间
- **从任一设备发布** - 什么方便用什么
- **没有严格的工作流** - 就用感觉对的

### 保持追踪

**通知：**

- 在移动版上为紧急事项启用
- 如果桌面通知让你分心，就把它关掉
- 或者两边都开，再有针对性地静音

**阅读状态：**

- Nostr 不追踪"已读"状态
- 你的客户端本地存储
- 同一条帖子在另一个客户端上可能再次显示为"新帖"
- 这是正常的，不是 bug

## 客户端特定功能（2 分钟）

### 按客户端划分的独特功能

**Damus（iOS）：**

- 最佳的 iOS 体验
- 流畅的动画
- 出色的通知
- Apple 生态系统集成

**Amethyst（Android）：**

- 最可定制
- 高级中继控制
- 非常适合高级用户
- 功能丰富

**Iris（网页版）：**

- 随处可用
- 快速且极简
- 适合桌面
- 简单界面

**Primal（所有平台）：**

- 精美设计
- 易于发现
- 统一体验
- 新手友好

**Snort（网页版）：**

- 键盘快捷键
- 快速性能
- 开发者友好
- 极简界面

**Coracle（网页版）：**

- 以中继为核心：自己挑中继，并逐个浏览
- 基于你的信任网络做内容过滤
- 社区、日历活动和分类信息
- 一个浏览器里可以登多个账号

### 基于任务的选择

凡是需要大段打字的事，桌面都更顺手；读东西、以及离开电脑时随手回一句，手机更合适。媒体和私信的差别更多来自客户端而不是设备，所以如果照片是你发布内容的主角，或者你想用上现行的私信标准，先确认某个客户端把这些做对了，再让它当你的主力。

<Callout variant="success">
  **实验：** 为不同任务尝试不同的客户端。你很快就会找到最适合你的。
</Callout>

## 备份与迁移（2 分钟）

### 在客户端之间移动

多加一个客户端很容易。真正值得做对的是你怎么登录它，因为 nsec 无法更换、也无法吊销：你把它粘贴进的每一个应用，都会永远留着它。

1. 安装新客户端
2. 按平台合适的方式登录（见下）
3. 等它把你的个人资料和关注拉回来
4. 开始使用

**网页客户端（Iris、Snort、Coracle、Primal 网页版）：** 接一个签名器扩展，[Alby](https://getalby.com) 或 [nos2x](https://github.com/fiatjaf/nos2x)，也可以用 [nsec.app](https://nsec.app) 这类远程签名器。网站每做一件事都要请签名器批准，它自己看不到你的密钥。不要把 nsec 粘贴到网站里，再有名的网站也不行。

**Android：** 用 [Amber](https://github.com/greenart7c3/Amber)。客户端把每个签名请求交给 Amber，你在 Amber 里批准，nsec 从头到尾没进过客户端。Amber 不在 Google Play 上，请从 F-Droid、Zap Store 或它的 GitHub 发布页获取。

**iOS：** App Store 上的应用是沙盒隔离的，所以常见做法是把 nsec 粘贴进一个你信得过的客户端。如果你根本不想把密钥交出去，Primal 可以通过它的 Remote Login 功能替其他 Nostr 应用批准操作，另外 [Nostash](https://apps.apple.com/us/app/nostash/id6744309333) 是 iPhone、iPad 和 Mac 上 Safari 的签名器扩展。

<Callout variant="warning">
  这和[快速上手](/zh/guides/quickstart)里说的是同一条规矩：网站让你在表单里输入私钥，就是危险信号，解法是用签名器。[隐私与安全](/zh/guides/privacy-security)会带你把签名器配起来。
</Callout>

**什么转移：**

- 身份
- 关注列表
- 个人资料信息
- 发布的帖子

**什么不转移：**

- 设置
- 草稿
- 本地数据

### 导出与导入

需要导出的东西比你想的少。你的关注和静音列表都是由你签名、发布到中继上的列表，新客户端只要连上正确的中继就会自己取回来，中间没有文件经手。在把书签存成 Nostr 列表（而不是存在本机）的客户端里，书签也是这样跟过来的。真正留在原地的是各应用自己的配置，而且只有一部分客户端提供保存它的办法。

### 测试新客户端

**安全方法：**

1. 先生成一对用完就扔的密钥
2. 用这个测试账号试客户端
3. 如果你喜欢它，再通过签名器接入你的真实身份
4. 保留旧客户端作为备份

**不要：**

- 把 nsec 粘贴到网站里，一次都不行
- 用你的主身份测试
- 匆忙迁移

## 高级工作流 [高级]

### 专业设置

**内容创作者：**

- **规划：** 你手边已经在用的任何笔记应用
- **写作：** 桌面客户端，全屏
- **互动：** 白天用手机
- **数据：** 打赏和触达的统计在另外的工具里，见[值得了解的 Nostr 工具](/zh/guides/nostr-tools)

**社区经理：**

- **监控：** 手机，始终在线
- **回复：** 桌面版，用来写长回复
- **活动：** 支持日历的客户端，比如 Coracle
- **数据：** 和上面同一批工具

跨平台转发的桥接和定时发布的机器人是有的，它们同时也是让一个账号读起来像信息流而不像一个人的最快途径。省着点用。

## 多客户端问题故障排除

### 不同步

**帖子不显示：**

- 不同的中继连接
- 等待几分钟
- 下拉刷新
- 检查中继状态

**关注不同：**

- 一个客户端没有完全同步
- 不同的中继集
- 等待并刷新

### 打开许久没用的客户端后，关注全没了

一个你几个月没碰的客户端，手里可能还攥着几个月前那份关注列表。如果你在它追上进度之前就关注或取关了谁，它就会把那份旧列表覆盖到当前列表上，你后来加的人全部消失。打开它，等它加载完，确认关注数看着没问题，然后再去关注任何人。

### 通知过载

**太多提醒：**

- 在较少使用的客户端上禁用
- 只保留移动版通知
- 策略性地使用勿扰模式

### 困惑

**迷失方向：**

- 选择主要和次要
- 使用一致的用户名
- 记录你的设置

## 快速参考

**同步：**

- ✓ 帖子、关注、个人资料（自动）
- ✗ 设置、草稿（手动）

**推荐配对：**

- iOS：Damus + Iris 网页版
- Android：Amethyst + Coracle 网页版
- 跨平台：到处使用 Primal

**最佳实践：**

- 为不同任务使用不同客户端
- 在网页上用签名器登录，绝不把 nsec 粘贴进网站
- 每个客户端都保持同一份中继列表
- 选择主要 + 次要
- 备份你的密钥（始终！）

**记住：** 多用几个客户端，等于多给自己留几条路。
