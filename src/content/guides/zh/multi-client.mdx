## 为什么使用多个客户端？（2 分钟）

### 选择的力量

Nostr 的超能力是你的身份到处都有效。聪明的用户通过将多个客户端用于不同目的来利用这一点。

### 常见用例

**移动 + 桌面：**

- **手机（Damus/Amethyst）：** 快速检查、随时随地发帖、通知
- **桌面（Iris/Snort）：** 长文写作、重度浏览、工作时间

**公共 + 私人：**

- **公共客户端：** 专业身份，公开帖子
- **私人客户端：** 个人身份，不同的圈子

**不同功能：**

- **客户端 A：** 媒体很棒
- **客户端 B：** 私信更好
- **客户端 C：** 发现最佳

**备份与冗余：**

- 如果一个客户端坏了，你有替代方案
- 安全地测试新功能
- 比较界面

### 好处

✅ **优化**

- 为每个任务使用最佳工具
- 不同情境下的不同界面
- 功能特定优势

✅ **灵活性**

- 不会锁定在一个界面
- 如果出现问题，易于切换
- 自由实验

✅ **生产力**

- 桌面用于写作
- 移动用于消费
- 分开的情境 = 更好的专注

<Callout type="info">
  **你不需要多个客户端。** 但如果你认真对待 Nostr，它会解锁新的工作流。
</Callout>

## 同步策略（3 分钟）

### 什么自动同步

**通用（跨所有客户端工作）：**

- ✓ 你的身份（npub）
- ✓ 你发布的帖子
- ✓ 关注列表
- ✓ 个人资料信息
- ✓ 反应（点赞、转发）
- ✓ 私信（如果正确加密）

### 什么不同步

**客户端特定：**

- ✗ 应用设置（主题、字体）
- ✗ 通知偏好
- ✗ 静音/屏蔽列表（有时）
- ✗ 草稿帖子
- ✗ 本地书签
- ✗ 自定义动态/算法
- ✗ 应用特定数据

### 同步过程

**工作原理：**

1. 你从客户端 A 发帖
2. 客户端 A 发送到中继
3. 客户端 B 连接到相同的中继
4. 客户端 B 看到你的帖子
5. 一切保持同步

**时间延迟：**

- 通常瞬间到几秒钟
- 取决于中继速度
- 客户端刷新率不同

### 非同步数据的解决方法

**设置：**

- 手动配置每个客户端
- 记录你的偏好
- 使用类似的设置以保持一致性

**静音/屏蔽：**

- 一些客户端导出/导入列表
- NIP-51 正在标准化
- 目前可能需要手动同步

**草稿：**

- 使用外部笔记应用
- 在客户端之间复制粘贴
- 或立即发布

**书签：**

- 使用 NIP-51 列表（如果支持）
- 外部书签工具
- 基于 Nostr 的书签服务

<Callout type="tip">
  **专业提示：** 专注于同步的内容（帖子、关注），不要太担心不同步的（设置）。
</Callout>

## 桌面 + 移动（3 分钟）

### 推荐配对

**iOS 用户：**

- **移动：** Damus（干净、快速）
- **桌面：** Iris（网页版）或 Snort（网页版）
- **为什么：** Damus 是 iOS 优化的，网页客户端随处工作

**Android 用户：**

- **移动：** Amethyst（功能丰富）
- **桌面：** Iris（网页版）或 Coracle（网页版）
- **为什么：** Amethyst 是 Android 的最佳选择，与快速网页客户端配对

**跨平台：**

- **移动：** Primal（iOS + Android）
- **桌面：** 相同的 Primal 账户（网页版）
- **为什么：** 跨设备统一体验

### 工作流示例

**内容创作者：**

- **在桌面起草**（Iris）- 写作、编辑、格式化
- **从桌面发布** - 点击发布
- **在移动版检查互动**（Damus）- 回复、闪电打赏
- **在移动版快速回复** - 在外出时

**社区经理：**

- **在移动版监控**（Amethyst）- 通知、提醒
- **在桌面深度互动**（Snort）- 长回复、线程
- **在移动版私信** - 快速对话
- **在桌面计划活动** - 详细帖子

**休闲用户：**

- **在移动版浏览**（任意）- 在休息时间
- **从任一设备发布** - 什么方便用什么
- **没有严格的工作流** - 就用感觉对的

### 保持追踪

**通知：**

- 在移动版上为紧急事项启用
- 如果在分心，在桌面版上禁用
- 或两者都启用，策略性地静音

**阅读状态：**

- Nostr 不追踪"已读"状态
- 你的客户端本地存储
- 可能在不同客户端上看到相同的帖子为"新"
- 这是正常的，不是 bug

## 客户端特定功能（2 分钟）

### 按客户端划分的独特功能

**Damus（iOS）：**

- 最佳的 iOS 体验
- 流畅的动画
- 出色的通知
- Apple 生态系统集成

**Amethyst（Android）：**

- 最可定制
- 高级中继控制
- 非常适合高级用户
- 功能丰富

**Iris（网页版）：**

- 随处工作
- 快速且极简
- 适合桌面
- 简单界面

**Primal（所有平台）：**

- 精美设计
- 易于发现
- 统一体验
- 新手友好

**Snort（网页版）：**

- 键盘快捷键
- 快速性能
- 开发者友好
- 极简界面

**Coracle（网页版）：**

- Matrix 集成
- 独特功能
- 良好性能
- 积极开发

### 基于任务的选择

**最适合发帖：**

- 桌面网页客户端（更大屏幕，更容易打字）
- 移动版用于快速想法

**最适合阅读：**

- 移动版（便利）
- 桌面版（更适合长内容）

**最适合媒体：**

- 图片/视频支持良好的客户端
- 检查哪些处理好照片/视频

**最适合私信：**

- 移动版（始终可用）
- 桌面版（更适合长对话）

<Callout type="tip">
  **实验：** 为不同任务尝试不同的客户端。你很快就会找到最适合你的。
</Callout>

## 备份与迁移（2 分钟）

### 在客户端之间移动

**简单（自动）：**

1. 安装新客户端
2. 导入你的 nsec
3. 等待同步（关注、个人资料）
4. 开始使用

**什么转移：**

- 身份
- 关注列表
- 个人资料信息
- 发布的帖子

**什么不转移：**

- 设置
- 草稿
- 本地数据

### 可用时导出/导入

**一些客户端支持：**

- 关注列表导出（NIP-02）
- 静音列表导出（NIP-51）
- 设置导出（专有的）

**如何：**

1. 转到设置 → 导出
2. 保存文件
3. 在新客户端导入
4. 验证数据已转移

### 测试新客户端

**安全方法：**

1. 首先创建测试密钥
2. 用测试账号尝试客户端
3. 如果你喜欢，导入真实密钥
4. 保留旧客户端作为备份

**不要：**

- 将 nsec 导入可疑客户端
- 用你的主身份测试
- 匆忙迁移

## 多客户端问题故障排除

### 不同步

**帖子不显示：**

- 不同的中继连接
- 等待几分钟
- 下拉刷新
- 检查中继状态

**关注不同：**

- 一个客户端没有完全同步
- 不同的中继集
- 等待并刷新

### 通知过载

**太多提醒：**

- 在较少使用的客户端上禁用
- 只保留移动版通知
- 策略性地使用勿扰模式

### 困惑

**迷失方向：**

- 选择主要和次要
- 使用一致的用户名
- 记录你的设置
