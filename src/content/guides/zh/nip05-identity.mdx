## 什么是 NIP-05？🆔

NIP-05（Nostr 实现可能性 #5）让你拥有一个人类可读的标识符，如 `you@domain.com`，而不是一长串随机字符。

### 它解决的问题

  panels={[
    {
      title: "NIP-05 之前",
      lines: ['关注：npub1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx', '"嘿，关注我！我是 npub1abc123…xyz789"'],
    },
    {
      title: "NIP-05 之后",
      tone: "positive",
      lines: ['关注：alice@example.com', '"嘿，关注我！我是 alice@example.com"'],
    },
  ]}
  caption="同一个身份，换成一个人真正念得出口的形式。"
/>

### 你得到什么

一个可以口口相传的地址。"在 bob@nostrplebs.com 找到我"这句话，在演出现场说出口、印在名片上、或者在播客结尾念一遍，都还立得住。它看起来是挑出来的，而不是生成出来的；大多数客户端允许别人用它来搜你，其中不少还会在旁边打一个小勾。在你依赖那个勾之前，最好先弄明白它是什么，下面的"信任"一节会讲清楚它证明了什么、又没证明什么。

### 但请记住...

> ⚠️ **NIP-05 是可选的。** 只有你的 npub，你也可以很好地使用 Nostr。

NIP-05 标识符是一个**便利**，不是必需的。你的 `npub` 是你在 Nostr 上的真实身份。

## 为什么获取 NIP-05？✨

### 更容易分享

```
在聚会上：
"你的 Nostr 是什么？"

没有 NIP-05：
"呃... n-p-u-b-one-x-x-x... 让我在手机上找找"

有 NIP-05：
"就是 alice@example.com"
```

### 专业外观

- **企业**：`support@yourcompany.com`
- **创作者**：`artist@yourdomain.com`
- **开发者**：`dev@opensourceproject.com`

### 信任与真实性

许多客户端为 NIP-05 用户显示 ✓ 徽章：

<MockProfile
  name="Alice"
  handle="alice@example.com"
  bio="比特币教育者"
  verified
  caption="通过验证的 NIP-05 地址，在大多数客户端里就是这样显示的。"
/>

那个徽章证明的东西，比它看上去要少。它只说明：地址里的那个域名，把那把特定的密钥发给了那个特定的名字。剩下的全看域名是谁的。`alice@alice.dev` 有分量，因为 alice.dev 是 Alice 的，别人在上面什么都发布不了。而挂在一个开放免费提供商下面的 `alice@`，只说明有人来要这个名字的时候它还没被占；冒充者去同一个提供商注册一个 `alicee@`，名字旁边会出现一模一样的勾。

所以该问的是：这个勾指向哪个域名。如果你认得出这个域名是本人的，那这个勾就确认了密钥属于他。如果这个域名你压根没听说过，这个勾对账号背后是谁没有任何交代。

### 你需要吗？

**不需要。** 没有它你也可以很好地使用 Nostr。

**但是...** 如果你符合以下情况，强烈推荐：

- 建立个人品牌
- 创建内容
- 经营企业
- 打算长期认真使用 Nostr
- 厌倦了念 63 个字符的字符串

### 不是中心化！

这是个合理的担心。如果你的名字住在别人的域名上，是不是等于把身份交出去了？并没有。地址只是一个指针，人们真正关注的是 npub。你可以同时持有好几个地址，也可以让其中一个到期作废，或者以后搬到自己的域名上，而你的粉丝一个都不会动，因为他们关注的是那把密钥。哪怕地址彻底丢了，你损失的也只是一点方便。账号、帖子和粉丝都毫发无损。

## 使用你自己的域名 🌐

为了完全控制和专业性，使用你自己的域名。

### 步骤 1：购买域名

任何域名注册商都可以：

- [Namecheap](https://namecheap.com)
- [Porkbun](https://porkbun.com)
- [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/)

费用：通常每年 $10-15

拥有域名只是一半。你还需要一个能替这个域名提供文件的地方，实际上就是你网站已经在用的那台主机。有些建站工具（Squarespace、Wix、Substack 之类）不允许你往一个叫 `.well-known` 的文件夹里放文件，而且在它们的编辑器里绕不过去。如果你用的正是这类工具，那就改用免费或付费的提供商；对读你东西的人来说，这个地址的效果完全一样。

### 步骤 2：创建 nostr.json 文件

在 `https://yourdomain.com/.well-known/nostr.json` 托管一个文件：

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

<Callout variant="warning" title="使用十六进制公钥，而不是 npub">
  NIP-05 要求使用公钥的小写十六进制原始形式。如果你把 `npub1...` 填进
  `nostr.json`，客户端将无法验证你的身份。而且是静默失败，不会给出任何提示。

有些客户端会在密钥设置的某处显示十六进制形式。如果你的客户端只肯给你看
`npub1...`，就把它粘贴到本页下方的检查工具里，那里会同时显示两种形式。

</Callout>

**完全不涉及 DNS 记录。** NIP-05 验证只是一个指向 `/.well-known/nostr.json`
的普通 HTTPS 请求。除了已经让域名指向你的网站服务器的那条记录之外，你不需要
TXT 记录、CNAME 或任何其他 DNS 条目。

有两项服务器设置决定了网页客户端能不能读到这个文件，而且它们出错的时候都不吭声。这个文件必须带上 `Access-Control-Allow-Origin: *` 这个响应头，浏览器里运行的客户端才读得到它；在大多数主机上这就是一行配置，你照这句话去问客服，他们会替你加上。另外，地址本身必须能直接应答。如果 `yourdomain.com` 会把访客弹到 `www.yourdomain.com`，验证就会失败，因为规范要求客户端忽略这个文件上的重定向。你在 NIP-05 地址里写的是哪一个，就必须由哪一个直接提供这个文件。

你的标识符变成：`alice@yourdomain.com`

### 示例设置演练

**场景：** 你拥有 `alice.dev`

1. **创建 JSON 文件：**

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

2. **上传到你的服务器：**

```
https://alice.dev/.well-known/nostr.json
```

3. **验证它是否有效：**
   在浏览器中打开：`https://alice.dev/.well-known/nostr.json`

4. **添加到 Nostr 个人资料：**
   在你的客户端中：设置 → 个人资料 → NIP-05 → `alice@alice.dev`

### 检查你的标识符

### 在你的客户端中

大多数客户端显示 NIP-05 状态：

**Damus/Amethyst：**

- 设置 → 个人资料 → NIP-05 字段
- 设置正确时显示 ✓

**Primal：**

- 个人资料显示 NIP-05 徽章
- 点击徽章查看详情

### 常见问题故障排除

先用上面的检查工具。把 `you@yourdomain.com` 粘进去，它会告诉你，客户端去查你的时候看到的是什么。下面这些清单讲的是拿到答案之后该怎么办。

**"NIP-05 无法工作"**

- **先检查密钥格式。** `nostr.json` 里必须填公钥的小写十六进制形式，64 个字符，不带 `npub1` 前缀。在这里填 npub，是 NIP-05 一直验证不通过的头号原因。
- 确保 JSON 有效（使用 JSON 验证器）
- 检查文件是否可以在确切的 URL 访问

**"找不到文件"**

- 确保 `.well-known` 文件夹已创建
- 检查你的服务器是否提供隐藏目录
- 验证路径：`/.well-known/nostr.json`

**"域名无法解析"**

- DNS 更改可能需要 24 小时
- 清除你的 DNS 缓存
- 可选，如果你用得惯终端：`dig yourdomain.com` 能告诉你这个域名解析了没有

**"客户端无法识别"**

- 一些客户端缓存 NIP-05 查询结果
- 尝试退出并重新登录
- 等待几分钟让传播完成

**"验证失败"错误**

**可能原因：**

1. **JSON 语法错误** - 检查缺少引号或逗号
2. **文件位置错误** - 必须位于 `/.well-known/nostr.json`
3. **缓存** - 等待 10-15 分钟并重试
4. **需要 HTTPS** - 必须通过 HTTPS 提供
5. **缺少 CORS 响应头** - 这个文件上没有 `Access-Control-Allow-Origin: *`，浏览器里运行的客户端就读不到它，哪怕你自己打开它一切正常
6. **中间挡着一次重定向** - 如果地址会在 `yourdomain.com` 和 `www.yourdomain.com` 之间来回跳，客户端会忽略这次重定向，然后放弃

**修复：**

- 在 jsonlint.com 验证 JSON
- 检查文件是否在确切路径
- 清除客户端缓存
- 确保 SSL 证书有效
- 让你的主机商为这个文件发送 `Access-Control-Allow-Origin: *`
- 把那个不做重定向、直接提供文件的主机名写进你的 NIP-05 地址

**"未找到"错误**

**可能原因：**

1. 文件未上传到正确位置
2. 服务器阻止点目录
3. 错误的域名

**修复：**

- 验证文件存在于确切的 URL
- 检查 `.htaccess` 或服务器配置允许点目录
- 确认你使用的是正确的域名

**提供商特定问题**

**NostrPlebs：**

- 登录管理门户，确认那里保存的 npub 和你的完全一致
- 确保 npub 正确（不是 nsec！）
- 如果卡住，联系支持

**自托管：**

- 跑一遍上面的检查工具，它会告诉你文件能不能取到、里面那把密钥是不是你的
- 确保文件权限允许读取
- 如果你有服务器日志的权限，去日志里找错误

<Callout variant="warning">
  设置 NIP-05 时永远不要分享你的 nsec（私钥）。只需要你的 npub（公钥）。
</Callout>

## 高级技巧 💡

### 多个身份

你可以有多个 NIP-05 地址：

```
personal@yourdomain.com
work@yourdomain.com
blog@yourdomain.com
```

都指向相同的 npub，或不同的。

### 子域名

使用子域名进行组织：

```
alice@team.yourdomain.com
alice@community.yourdomain.com
```

### 托管多个用户

你可以在一个域名上托管多个 NIP-05 标识符：

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9",
    "bob": "3bf0c63fcb93463407af97a5e5ee64fa883d107ef9e558472c4eb9aaaefa459d",
    "carol": "82341f882b6eabcd2ba7f1ef90aad961cf074af15b9ef44a09f9d2a8fbfbe6a2"
  }
}
```

### 验证你的设置

**方法 1：你的客户端**

1. 将 NIP-05 添加到个人资料
2. 保存更改
3. 寻找对勾 ✓ 或"已验证"徽章
4. 可能需要几分钟让传播完成

**方法 2：Nostr 浏览工具**

1. 在浏览器里打开 `njump.me/yourname@yourdomain.com`
2. 如果你的个人资料出现了，说明你的 NIP-05 解析到了你的密钥

**方法 3：直接测试（命令行，可选）**

```bash
curl https://yourdomain.com/.well-known/nostr.json
```

**成功看起来像这样：**

- ✅ 客户端显示验证徽章
- ✅ 其他人可以通过你的 NIP-05 找到你
- ✅ 你的个人资料显示你的人类可读名称

### 隐私考虑

NIP-05 地址把你的密钥和一个域名绑在一起，而域名是谁都能去查的。如果这个域名登记在你本人名下，或者上面那个网站本来就摆着你的简介和照片，这个地址就悄悄把一个化名账号接到了你生活的其余部分上。有时候这正是你要的。如果不是，就把化名账号留在免费提供商的域名上，自己的域名留给那些你乐意署真名的作品。
