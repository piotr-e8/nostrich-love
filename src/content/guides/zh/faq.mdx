### Nostr 到底是什么？

Nostr 是一个**协议**——就像电子邮件或网络。它定义了消息如何在客户端和中继之间移动。这意味着：

- 没有单一公司拥有或控制它
- 你可以在不丢失身份的情况下切换应用
- 任何人都可以构建自己的应用或中继
- 你控制自己的密钥和数据

[了解更多：什么是 Nostr？ →](/zh/guides/what-is-nostr)

<FAQAccordion 
  question="npub 和 nsec 有什么区别？我应该分享哪一个？"
  category="security"
  client:load
>
  这两个密钥协同工作：

**npub**（公钥）= 你的用户名

- 以：`npub1...` 开头
- **可以安全分享** 🟢
- 这是你在 Nostr 上的公开身份
- 在任何你想让人找到你的地方分享

**nsec**（私钥）= 你的密码

- 以：`nsec1...` 开头
- **永远不要分享** 🔴
- 这证明你拥有你的 npub
- 任何拥有它的人都可以以你的身份发帖
- 丢失它 = 永远丢失你的账号

**简单规则：** 如果以"npub"开头，分享它。如果以"nsec"开头，像保护你的生命一样保护它。

[了解更多：密钥与安全 →](/zh/guides/keys-and-security)

</FAQAccordion>

<FAQAccordion 
  question="如果我丢失了私钥，我能恢复我的账号吗？"
  category="security"
  client:load
>
  **不能。没有恢复。**

Nostr 没有：

- "忘记密码"按钮
- 客服支持
- 可以重置账号的管理员
- 账号恢复流程

这是设计如此。Nostr 是去中心化的，这意味着没有中央机构可以求助。

**你能做什么：**

1. **预防：** 在 3 个以上的地方备份你的 nsec（遵循 3-2-1 规则）
2. **缓解：** 创建一个新的密钥对并告诉你的粉丝你的新账号
3. **NIP-05：** 如果你有 NIP-05 标识符，你可以将其重定向到你的新 npub

**说实话：** 人们每天都在失去账号访问权限。不要成为他们之一。现在就备份你的密钥。

[了解更多：3-2-1 备份规则 →](/zh/guides/keys-and-security#the-3-2-1-backup-rule)

</FAQAccordion>

<FAQAccordion 
  question="为什么我需要保存这些长串字符？"
  category="basics"
  client:load
>
  那些"长串"是加密密钥。以下是它们看起来像乱码的原因：

**256 位安全：** 每个密钥的可能组合比可观测宇宙中的原子还多。这让它不可能被猜到。

**单向数学：** 你无法从公钥推算出私钥。这在数学上是不可能的。

**没有中央数据库：** 与 Twitter 或 Facebook 不同，没有公司存储"用户名：密码"对。你的密钥就是你的身份。

**为什么不简单点？**

- 简单密码会被黑客入侵
- 中心化数据库会被破坏
- 你的身份需要真正属于你——而这需要严肃的密码学

**好消息：** 你不会经常输入这些。大多数客户端安全地存储它们。你只需要安全备份。

<FAQAccordion 
  question="什么是 NIP-05 标识符？我需要吗？"
  category="advanced"
  client:load
>
  NIP-05 标识符就像 Nostr 的人类可读用户名。

**没有 NIP-05：** 你由你的 npub 标识

- `npub1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqq`

**有 NIP-05：** 你由可读的东西标识

- `you@example.com` 或 `you@nostrplebs.com`

**好处：**

- 容易记住和分享
- 看起来更专业
- 可以被验证（证明你控制该域名）
- 一些客户端在搜索中优先显示 NIP-05 用户

**你需要吗？**

- **不是必需的。** 没有它你也可以很好地使用 Nostr
- **如果你认真对待 Nostr，推荐**
- **如果你正在建立品牌或公众形象，必需**

**如何获得：**

1. 从提供商处购买（nostrplebs.com、nostrname.com）- 每年 $5-15
2. 设置你自己的域名（如果你拥有）- 免费
3. 一些服务提供免费选项

- ✓ 你的身份（相同的 npub）

- ✓ 你的关注列表

- ✗ 应用特定设置（主题、偏好）
- ✗ 草稿帖子（如果未发布）

**如何切换：**

1. 从当前客户端导出你的 nsec（或使用你的备份）
2. 安装新客户端
3. 导入/输入你的 nsec
4. 等待数据从中继同步
5. 你恢复业务了！

这就是为什么 Nostr 很强大——你永远不会被困在一个应用中。

<FAQAccordion 
  question="为什么看不到我的旧帖子？"
  category="troubleshooting"
  client:load
>
  **这通常发生在三个原因之一：**

**原因 1：中继存储限制**

- 你的帖子存储在中继上
- 如果中继宕机，帖子可能暂时消失
- **修复：** 连接到多个中继

**原因 2：新客户端/数据同步**

- 当你登录新客户端时，需要时间来获取旧帖子
- 一些客户端最初只获取最近的历史
- **修复：** 等待几分钟，或手动刷新

**原因 3：客户端缓存**

- 一些客户端在本地缓存数据
- 如果缓存清除，它们需要重新获取
- **修复：** 下拉刷新，或重启应用

**如何防止：**

1. **使用多个中继** - 不要只依赖一个
2. **发布到可靠的中继** - 它们有更好的正常运行时间
3. **[高级] 使用备份服务** - 一些服务存档你的帖子
4. **定期导出数据** - 在本地保存你的内容

**重要提示：** 即使你看不到旧帖子，它们可能仍然存在于中继上。尝试：

- 不同的客户端
- 不同的中继
- Nostr 探索器（nostr.guru）

**Nostr 中的数据持久性：**

- 帖子可以在中继上无限期存在
- 但中继也可以删除旧数据
- 除非你备份，否则没有什么是真正"永久"的

<FAQAccordion 
  question="如果中继删除我的内容会发生什么？"
  category="technical"
  client:load
>
  如果一个中继删除你的内容，它仍然存在于你连接的其他中继上。然而，该特定中继上的新用户将看不到历史帖子。这就是为什么建议使用多个中继——你的数据是分布式的，不是中心化的。你可以随时重新发布到新中继。

**删除的工作原理：**

- ❌ 从一个中继删除 ≠ 到处都删除
- ✅ 内容保留在你连接的其他中继上
- ✅ 新中继可以从现有的同步
- ⚠️ 删除中继上的新用户将看不到旧帖子

<Callout variant="success">
  使用 5-10 个中继以获得冗余。你的内容是分布式的，使单点删除无效。
</Callout>

</FAQAccordion>

<FAQAccordion 
  question="我可以编辑或删除帖子吗？"
  category="basics"
  client:load
>
  Nostr 帖子是不可变的——发布后无法编辑。你可以发布更正或后续说明。对于删除，你可以发送删除请求，但中继可能选择不执行。发帖前三思——持久性是协议的一个特性。

**现实：**

- **无法编辑** - 改为发布更正
- **删除请求** - 发送但不保证
- **中继酌情** - 每个中继决定是否执行删除请求
- **假设持久性** - 始终以此心态发帖

<Callout variant="warning">
  发帖前三思！Nostr 是为持久性设计的。发布后，内容可能在中继上无限期存在。
</Callout>

</FAQAccordion>

<FAQAccordion 
  question="为什么我在不同客户端看到不同的内容？"
  category="technical"
  client:load
>
  每个客户端连接到不同的默认中继。你的动态取决于你连接哪些中继以及你关注谁。如果中继 A 与中继 B 有不同的用户，你会看到不同的内容。这是正常的——添加更多中继或关注更多人，以在各个客户端看到一致的内容。

**动态不同的原因：**

- 默认中继列表因客户端而异
- 不同的中继连接 = 不同的内容
- 客户端之间的同步时间不同
- 个人中继设置影响可见性

**一致性的解决方案：**

1. 在各个客户端使用相同的中继
2. 切换时导入你的中继列表
3. 关注更多人以增加重叠
4. 允许初始同步时间

</FAQAccordion>

<FAQAccordion

2. **事件导出** - 使用 nostr-fetch CLI 工具

- `nak` - 用于各种任务的 Nostr 瑞士军刀

<Callout variant="info">

<FAQAccordion 
  question="NIP-04 和 NIP-17 私信有什么区别？"
  category="advanced"
  client:load
>
  NIP-04（已弃用）使用共享密钥加密，存在已知漏洞。NIP-17（推荐）使用密封发送者和礼物包装以获得更好的隐私。NIP-17 隐藏关于谁在向谁发送消息的元数据。迁移到支持 NIP-17 的客户端以获得安全的私人消息。

**对比：**

| 特性             | NIP-04（旧）  | NIP-17（新） |
| ---------------- | ------------- | ------------ |
| 内容加密  | ✅ 是        | ✅ 是       |
| 元数据保护 | ❌ 否         | ✅ 是       |
| 安全性            | ⚠️ 有漏洞 | ✅ 安全    |
| 状态              | 已弃用    | 推荐      |

<Callout variant="success">
  检查你的客户端设置并升级到 NIP-17。现代客户端如 Amethyst、Damus 和 Primal 支持它。
</Callout>

</FAQAccordion>

<FAQAccordion 
  question="我的私信真的私密吗？"
  category="security"
  client:load
>
  使用 NIP-17（推荐）：是的，内容是加密的，元数据被最小化。使用旧的 NIP-04：内容是加密的，但元数据泄露是可能的。使用中继操作员可以看到你在发消息，但使用 NIP-17 看不到内容或确切的接收者。为了最大隐私，还使用 VPN/Tor。

**隐私级别：**

**NIP-17（使用这个！）：**

- ✅ 内容端到端加密
- ✅ 元数据最小化（密封发送者）
- ⚠️ 中继看到加密活动

**NIP-04（已弃用）：**

- ✅ 内容加密
- ❌ 元数据泄露可能
- ❌ 已知漏洞

<Callout variant="info">
  为了最大隐私，将 NIP-17 与 VPN 或 Tor 结合使用。这向中继隐藏你的 IP。
</Callout>

<FAQAccordion 
  question="如果有人猜到我的 npub，他们能窃取我的账号吗？"
  category="security"
  client:load
>
  不会。你的 npub（公钥）是要分享的——就像你的用户名。你的 nsec（私钥）是你的密码。保密 nsec。仅知道 npub 无法危害你的账号。自由分享你的 npub，虔诚地保护你的 nsec。

**关键事实：**

- **npub** = 公共用户名 ✅ 自由分享
- **nsec** = 私人密码 🔒 永远不要分享
- **数学** - 无法从 npub 推导出 nsec
- **安全性** - 256 位密码学保护你

<Callout variant="success">
  到处发布你的 npub！它是设计为公开的。只有你的 nsec 需要保护。
</Callout>

</FAQAccordion>

<FAQAccordion

**你的工具：**

<FAQAccordion 
  question="什么是'垃圾邮件过滤器'，它们如何工作？"
  category="advanced"
  client:load
>
  垃圾邮件过滤器是客户端端算法，隐藏低质量内容。它们分析：账号年龄、信任网络、内容模式、打赏收据。每个客户端实现不同。你通常可以调整敏感度或禁用。会有误报——如果错过合法帖子，检查"显示全部"。

**过滤器的工作原理：**

- **账号年龄** - 较新的账号被更严格地过滤
- **信任网络** - 谁关注他们很重要
- **内容模式** - 重复/垃圾行为检测
- **打赏历史** - 接收打赏的账号更可信

**调整过滤器：**

- 大多数客户端允许你更改敏感度
- 如果需要可以完全禁用
- 定期检查过滤/垃圾邮件文件夹
- 向客户端开发者报告误报

<Callout variant="info">
  过滤器是客户端端的，不是全网范围的。如果你不喜欢当前过滤器的行为，切换客户端。
</Callout>

</FAQAccordion>

<FAQAccordion 
  question="为什么我的动态突然显示旧帖子？"
  category="troubleshooting"
  client:load
>
  当以下情况发生时：你连接到带有旧数据的新中继，你的客户端从中继重新同步，或有人打赏旧帖子将其置顶。Nostr 没有按时间顺序的"动态"——它来自多个来源的聚合。旧帖子重新出现是正常行为。

**旧帖子出现的原因：**

- **新中继** - 连接到带有旧缓存数据的中继
- **重新同步** - 客户端从中继刷新
- **打赏活动** - 有人打赏旧帖子
- **算法** - 一些客户端显示热门旧内容

**这是正常的！**

与 Twitter 的按时间顺序动态不同，Nostr 从许多来源聚合。内容没有单一的"时间"——它存在于它存在的地方。

</FAQAccordion>

<FAQAccordion 
  question="闪电打赏在技术上是如何工作的？"
  category="advanced"
  client:load
>
  闪电打赏使用比特币闪电网络。流程：1）发送者创建闪电发票，2）发送者发布带有支付证明的打赏收据（kind 9735），3）客户端显示带有发送者个人资料的打赏，4）接收者在他们的闪电钱包中收到聪。NIP-57 将其标准化。没有托管或平台——直接的 P2P 支付。

**技术流程：**

1. **发票创建** - 发送者的钱包创建闪电发票
2. **支付** - 发送者支付发票
3. **收据** - 发布带有支付证明的 Kind 9735 事件
4. **显示** - 客户端显示带有发送者信息的打赏
5. **结算** - 接收者在他们的钱包中收到聪

**关键点：**

- 使用 NIP-57 标准
- 直接 P2P（没有中间人）
- 即时结算
- 公共收据创造社交证明
- 可选的私人打赏可用

<Callout variant="info">
  闪电打赏是非托管的——资金直接从发送者流向接收者。没有平台持有资金。
</Callout>
