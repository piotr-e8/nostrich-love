## NIP-05 क्या है? 🆔

NIP-05 (Nostr Implementation Possibility #5) आपको एक मानव-पठनीय पहचानकर्ता जैसे `you@domain.com` रखने की अनुमति देता है, जबकि लंबी रैंडम कैरेक्टर स्ट्रिंग के बजाय।

### यह जो समस्या हल करता है

```
NIP-05 से पहले:
┌──────────────────────────────────────────────┐
│ Follow: npub1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  │
│ "अरे, मुझे फॉलो करो! मैं npub1abc123...xyz789 हूं"   │
└──────────────────────────────────────────────┘
                 ↓
NIP-05 के बाद:
┌──────────────────────────────────────────────┐
│ Follow: alice@example.com                    │
│ "अरे, मुझे फॉलो करो! मैं alice@example.com हूं"      │
└──────────────────────────────────────────────┘
```

### आपको क्या मिलता है

- ✅ **आसानी से साझा करने योग्य**: "bob@nostrplebs.com पर मुझे ढूंढें"
- ✅ **पेशेवर दिखता है**: क्लीन, यादगार पहचानकर्ता
- ✅ **ट्रस्ट सिग्नल**: कई क्लाइंट में NIP-05 बैज
- ✅ **खोजने में आसान**: अपने पहचानकर्ता द्वारा खोजें

### लेकिन याद रखें...

> ⚠️ **NIP-05 वैकल्पिक है।** आप केवल अपने npub के साथ पूरी तरह से Nostr का उपयोग कर सकते हैं।

NIP-05 पहचानकर्ता एक **सुविधा** है, जरूरत नहीं। आपका `npub` आपकी वास्तविक पहचान है Nostr पर।

## NIP-05 क्यों प्राप्त करें? ✨

### आसानी से साझा करने योग्य

```
एक पार्टी में:
"आपका Nostr क्या है?"

NIP-05 के बिना:
"उम्म... n-p-u-b-one-x-x-x... मुझे फोन में ढूंढने दो"

NIP-05 के साथ:
"बस alice@example.com"
```

### पेशेवर उपस्थिति

- **बिज़नस**: `support@yourcompany.com`
- **क्रिएटर**: `artist@yourdomain.com`
- **डेवलपर**: `dev@opensourceproject.com`

### ट्रस्ट और ऑथेंटिसिटी

कई क्लाइंट NIP-05 यूज़र्स के लिए ✓ बैज दिखाते हैं:

```
┌─────────────────────┐
│ 👤 Alice ✓          │
│ alice@example.com   │
│ "Bitcoin शिक्षक"      │
└─────────────────────┘
```

यह लोगों को पता लगाने में मदद करता है कि वे असली आप को फॉलो कर रहे हैं, न कि धोखेबाज।

### क्या आपको एक की जरूरत है?

**नहीं।** आप इसके बिना पूरी तरह से Nostr का उपयोग कर सकते हैं।

**लेकिन...** यह अत्यधिक अनुशंसित है अगर आप:

- एक व्यक्तिगत ब्रांड बना रहे हैं
- कंटेंट बना रहे हैं
- एक बिज़नस चला रहे हैं
- Nostr को दीर्घकालिक लेकर सीरियस हैं
- 63-कैरेक्टर स्ट्रिंग पढ़ने से थक गए हैं

### सेंट्रलाइज़ेशन नहीं!

कुछ लोग चिंतित हैं कि NIP-05 का मतलब "सेंट्रलाइज़्ड आइडेंटिटी" है। ऐसा नहीं है:

- आपके पास **मल्टीपल** NIP-05 पहचानकर्ता हो सकते हैं
- आप उन्हें कभी भी **बदल** सकते हैं
- आपका **npub** अभी भी आपकी वास्तविक पहचान है
- NIP-05 आपके npub का केवल एक **पॉइंटर** है

| 4 कैरेक्टर   | २२,५०० sats (~$१४) |
| 5+ कैरेक्टर  | १२,५०० sats (~$८)  |

*नोट: कुछ विशेष नामों की कीमतें बढ़ी हो सकती हैं। USD में कीमतें वर्तमान बिटकॉइन दरों पर आधारित अनुमानित हैं।*

**उपलब्ध डोमेन:**

- `nostrplebs.com` - बेसिक मेम्बरशिप
- `nostriches.net` - बेसिक मेम्बरशिप  
- `nostr.fan` - बेसिक मेम्बरशिप
- `nostrich.zone` - बेसिक मेम्बरशिप

- Nostr Plebs रिले तक पहुंच

1. [nostrplebs.com](https://nostrplebs.com) पर जाएं

5. मैनेजमेंट पोर्टल के माध्यम से अपना npub जोड़ें

## अपना खुद का डोमेन उपयोग करना 🌐

पूर्ण नियंत्रण और पेशेवरता के लिए, अपना खुद का डोमेन उपयोग करें।

### चरण १: डोमेन खरीदें

कोई भी डोमेन रजिस्ट्रार काम करता है:

- [Namecheap](https://namecheap.com)
- [Porkbun](https://porkbun.com)
- [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/)

लागत: आमतौर पर $१०-१५/वर्ष

### चरण २: nostr.json फ़ाइल बनाएं

`https://yourdomain.com/.well-known/nostr.json` पर एक फाइल होस्ट करें:

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

<Callout variant="warning" title="अपनी सार्वजनिक कुंजी hex में डालें, npub नहीं">
  NIP-05 को आपकी सार्वजनिक कुंजी lowercase hex रूप में चाहिए। अगर आप
  `nostr.json` में `npub1...` डालते हैं, तो कोई भी क्लाइंट आपको सत्यापित नहीं कर
  पाएगा — और यह चुपचाप विफल होगा, बिना किसी संदेश के।

ज़्यादातर क्लाइंट hex रूप को सेटिंग्स → कुंजियाँ में "public key (hex)" नाम से
दिखाते हैं। आप अपना npub इस पृष्ठ पर नीचे दिए गए टूल में भी डाल सकते हैं, जो
दोनों रूप साथ-साथ दिखाता है।

</Callout>

**इसमें कोई DNS रिकॉर्ड शामिल नहीं है।** NIP-05 सत्यापन `/.well-known/nostr.json`
के लिए एक सामान्य HTTPS अनुरोध भर है। आपको TXT रिकॉर्ड, CNAME या कोई अन्य DNS
प्रविष्टि नहीं चाहिए — सिवाय उसके जो पहले से आपके डोमेन को आपके वेब होस्ट पर
भेजती है।

आपका पहचानकर्ता बन जाता है: `alice@yourdomain.com`

### उदाहरण सेटअप वॉकथ्रू

**परिदृश्य:** आप `alice.dev` के मालिक हैं

1. **JSON फाइल बनाएं:**

```json
{
  "names": {
    "alice": "b0635d6a9851d3aed0cd6c495b282167acf761729078d975fc341b22650b07b9"
  }
}
```

2. **अपने सर्वर पर अपलोड करें:**

```
https://alice.dev/.well-known/nostr.json
```

3. **वेरिफाई करें कि यह काम करता है:**
   ब्राउज़र में खोलें: `https://alice.dev/.well-known/nostr.json`

4. **अपने Nostr प्रोफाइल में जोड़ें:**
   अपने क्लाइंट में: Settings → Profile → NIP-05 → `alice@alice.dev`

### अपने क्लाइंट में

अधिकांश क्लाइंट NIP-05 स्टेटस दिखाते हैं:

**Damus/Amethyst:**

- Settings → Profile → NIP-05 फील्ड
- जब सही से सेट हो तो ✓ दिखाता है

**Primal:**

- प्रोफाइल NIP-05 बैज दिखाता है
- विवरण देखने के लिए बैज पर क्लिक करें

### सामान्य समस्याओं का निवारण

**"NIP-05 काम नहीं कर रहा"**

- nostr.json में अपना npub सही है यह डबल-चेक करें
- सुनिश्चित करें कि JSON वैलिड है (JSON वैलिडेटर उपयोग करें)
- चेक करें कि फाइल सही URL पर एक्सेसिबल है

**"फाइल नहीं मिली"**

- सुनिश्चित करें कि `.well-known` फोल्डर बनाया गया है
- अपने सर्वर को छिपी हुई डायरेक्टरीज़ सर्व करने के लिए चेक करें
- पथ वेरिफाई करें: `/.well-known/nostr.json`

**"डोमेन रिज़ॉल्व नहीं हो रहा"**

- DNS परिवर्तनों में २४ घंटे तक लग सकते हैं
- अपना DNS कैश क्लियर करें
- `dig` या `nslookup` कमांड से चेक करें

**"क्लाइंट इसे पहचान नहीं रहा"**

- कुछ क्लाइंट NIP-05 लुकअप रिजल्ट कैश करते हैं
- लॉग आउट और वापस लॉग इन ट्राई करें
- प्रोपेगेशन के लिए कुछ मिनट इंतज़ार करें

**"वेरिफिकेशन विफल" एरर**

**संभावित कारण:**

1. **JSON सिंटेक्स एरर** - मिसिंग कोट्स या कॉमा चेक करें
2. **गलत फाइल लोकेशन** - `/.well-known/nostr.json` पर होना चाहिए
3. **कैशिंग** - १०-१५ मिनट इंतज़ार करें और रीट्राई करें
4. **HTTPS आवश्यक** - HTTPS पर सर्व किया जाना चाहिए

**फिक्स:**

- jsonlint.com पर JSON वैलिडेट करें
- चेक करें फाइल सही पथ पर है
- क्लाइंट कैश क्लियर करें
- सुनिश्चित करें SSL सर्टिफिकेट वैलिड है

**"नहीं मिला" एरर**

**संभावित कारण:**

1. फाइल सही लोकेशन पर अपलोड नहीं
2. सर्वर डॉट-डायरेक्टरीज़ ब्लॉक करता है
3. गलत डोमेन

**फिक्स:**

- वेरिफाई करें फाइल सही URL पर मौजूद है
- `.htaccess` या सर्वर कॉन्फिग चेक करें जो डॉट-डायरेक्टरीज़ को अलाउ करता है
- कन्फर्म करें आप सही डोमेन उपयोग कर रहे हैं

**प्रोवाइडर-विशिष्ट समस्याएँ**

**NostrPlebs:**

- वेरिफिकेशन ईमेल के लिए स्पैम फोल्डर चेक करें
- सुनिश्चित करें npub सही है (nsec नहीं!)
- अगर फंस गए तो सपोर्ट से संपर्क करें

**सेल्फ-होस्टेड:**

- DNS प्रोपेगेशन वेरिफाई करें: `dig yourdomain.com`
- एरर्स के लिए सर्वर लॉग्स चेक करें
- सुनिश्चित करें फाइल परमिशन्स रीडिंग अलाउ करती हैं

<Callout variant="warning">
  NIP-05 सेटअप करते समय अपना nsec (प्राइवेट की) कभी साझा न करें। केवल आपका npub
  (पब्लिक की) जरूरी है।
</Callout>

```

    "carol": "82341f882b6eabcd2ba7f1ef90aad961cf074af15b9ef44a09f9d2a8fbfbe6a2"
  }
}
```

### अपने सेटअप को वेरिफाई करना

**विधि १: आपका क्लाइंट**

1. NIP-05 को अपने प्रोफाइल में जोड़ें
2. बदलाव सेव करें
3. चेकमार्क ✓ या "verified" बैज देखें
4. प्रोपेगेट होने में कुछ मिनट लग सकते हैं

**विधि २: Nostr एक्सप्लोरर**

1. nostr.guru जैसे Nostr एक्सप्लोरर पर जाएं
2. अपने NIP-05 खोजें
3. चेक करें कि यह आपके npub को रिज़ॉल्व करता है

**विधि ३: डायरेक्ट टेस्ट (कमांड लाइन)**

```bash
curl https://yourdomain.com/.well-known/nostr.json
```

**सफलता कैसी दिखती है:**

- ✅ क्लाइंट वेरिफिकेशन बैज दिखाता है
- ✅ दूसरे आपको आपके NIP-05 से ढूंढ सकते हैं
- ✅ आपका प्रोफाइल आपका मानव-पठनीय नाम दिखाता है

### प्राइवेसी विचार

- NIP-05 आपके npub को एक डोमेन से लिंक करता है
- यह आपकी डी-ऑनॉनिमाइज़ कर सकता है अगर डोमेन में आपकी वास्तविक जानकारी है
- स्यूडोनाइमस अकाउंट्स के लिए मुफ्त प्रोवाइडर्स उपयोग करें
- अपना खुद का डोमेन उपयोग करें जब आप पहचाने जाना चाहते हैं
